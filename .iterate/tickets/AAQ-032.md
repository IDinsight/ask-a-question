- No index on `workspace_id` in `content`, `tag`, `urgency_rule`, `query`, `query_response`, `content_feedback`, `query_response_feedback`, `urgency_query`, `urgency_response`, `user_workspace`; none on `query(workspace_id, query_datetime_utc)` used by data_api/dashboard.
- No DB uniqueness for `(workspace_id, tag_name)` (app-only check `tags/routers.py:90`) or `(workspace_id, display_number)` (max+1, `contents/models.py:164,646-673`).
- `ContentDB.__table_args__` uses set-literal braces and ops key `"embedding"` while the column is `content_embedding` (`contents/models.py:53-62`); doesn't match migration `2025_02_23_79c762e9b073…:265-274`.

## What needs to change
- Migration: separate data step de-duplicating existing rows, then add indexes and unique constraints.
- Fix the ORM `Index` to match the migration.
- Map `IntegrityError` → `ConflictError` in persistence.
