**Target:** dsem Level 3 · **Skill:** dsem-security, dsem-api-skill

## What's wrong now
- Read routes trust the JWT `workspace_name` claim without checking membership (`auth/dependencies.py:277-319`): `contents/routers.py:298,636`, `tags/routers.py:182,278`, `urgency_rules/routers.py:104,295`, all 7 dashboard routes, `workspaces/routers.py:230`.
- `authenticate_key` JWT fallback (`auth/dependencies.py:176-189`) returns the workspace by name without checking the user exists or is a member — exposes `/data-api/*` (raw end-user queries) and QA endpoints.
- A removed user keeps read access for the token lifetime; a renamed workspace's old name can later resolve to a different workspace.
- Role checks are copy-pasted inline 24× across 7 routers (e.g. `contents/routers.py:120-131`).
- Auth dependencies open their own `AsyncSession(get_sqlalchemy_async_engine())` (`auth/dependencies.py:75,169,264`, `auth/routers.py:205`), so tests cannot override them and each request opens an extra connection.

## What needs to change
- Add `require_workspace_role(*roles)` in `app/auth/dependencies.py` returning `(user, workspace, role)` after joining `UserWorkspaceDB` on `sub` + `workspace_id`; use it on every admin-app route.
- In the API-key JWT fallback, require current membership (decide whether READ_ONLY may call the data API); return 403 for non-members.
- Inject `Depends(get_async_session)` into auth dependencies; replace all inline role checks.

## Done when
- No router calls `user_has_required_role_in_workspace` directly.
- With a removed user's old token, `GET /content`, `/dashboard/overview/{tf}`, `/data-api/queries`, `/workspace/current-workspace` return 403; renamed-workspace test passes.
- `app.dependency_overrides[get_async_session]` affects auth dependencies; existing 401/403 tests pass.
