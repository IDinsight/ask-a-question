**Target:** dsem Level 3 · **Skill:** dsem-security, dsem-api-setup (observability.md)

## What's wrong now
- `question_answer/routers.py:810` logs end-user query text at INFO; `speech_components/utils.py:224` logs upstream response bodies.
- `@observe()` on `chat` (`question_answer/routers.py:204`) receives `QueryBase` which includes `turnio_api_key` (`schemas.py:40`) — likely sent to Langfuse when `LANGFUSE=True` (not runtime-verified).
- No redaction filter (`app/utils.py:422-459`).

## What needs to change
- Logging filter masking `authorization`, `token`, `password`, `api_key`, `recovery_code` patterns (implement in the loguru setup from B1).
- Log query IDs instead of query text.
- Exclude `turnio_api_key` from observed inputs (`capture_input=False` / strip) or move it to a header.

## Done when
- caplog test proves password, token and Turn.io key never appear in logs.
- Langfuse trace fixture shows the key absent.
