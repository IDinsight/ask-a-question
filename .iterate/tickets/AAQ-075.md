**Target:** dsem Level 3 · **Skill:** dsem-documentation (references/readme.md env table)

## What's wrong now
- No required/optional env table. Contradictions: `.env.example:8` says the backend doesn't load `.env` but `app/__init__.py:13-15` does; `.env.example:45-46` points at `app/database.py` and `DATABASE_URL` is unused; template lists `ADMIN_API_KEY`, `ADMIN_CONTENT_QUOTA`, `ADMIN_API_DAILY_QUOTA` that no code reads; `HTTPX_TIMEOUT` is hard-coded (`core/config.py:125`); template `N_TOP_CONTENT=5` vs code default 4 (`question_answer/config.py:7`); `PROMETHEUS_MULTIPROC_DIR` effectively required but not flagged.
- admin_app reads `NEXT_PUBLIC_BACKEND_URL` and `NEXT_PUBLIC_GOOGLE_LOGIN_CLIENT_ID` via `next-runtime-env`; no `admin_app/.env.example`.

## What needs to change
- Configuration table (name | required | default | read in | purpose) in `core_backend/README.md` covering every var from `app/core/config.py`, `app/auth/config.py`, `app/question_answer/config.py`, `app/dashboard/config.py`, `app/urgency_detection/config.py`, `app/docmuncher/dependencies.py:46`, `app/users/routers.py:262`, and the dummy-data script — regenerated from the S2 Settings class.
- Two-row table + `admin_app/.env.example` with placeholders.
- Fix false statements in `.env.example` and `template.core_backend.env`; point `docs/deployment/config-options.md` at the table.

## Done when
- Every env read under `core_backend/app` and every `env("NEXT_PUBLIC_*")` in `admin_app/src` is in a table with required/optional; no documented var is unread (or it's marked script-only/unused).
