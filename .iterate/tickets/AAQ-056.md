**Target:** dsem Level 3 · **Skill:** dsem-ci-cd (github-actions-python.md), dsem-api-setup

## What's wrong now
- `core_backend/pyproject.toml` + `uv.lock` exist (`uv lock --check` passes) but nothing uses them: CI (`tests.yaml:52-53,101-102`, `linting.yaml:28-29`, `alembic-migrations.yaml:35,54`, `retrieval-validation.yaml:57`) and `core_backend/Dockerfile:24-25` install `requirements.txt` (transitive deps unpinned).
- Drift already: `slowapi>=0.1.10` in `pyproject.toml:54` but not `requirements.txt` (and unused in code).
- No `[dependency-groups] dev` — pytest/ruff/mypy aren't installable via `uv sync`; pytest config lives in root `pyproject.toml`; `core_backend/Makefile:4` uses `$(shell which python)`; root Makefile `fresh-env` uses conda.
- CI installs torch from PyPI while the Dockerfile uses the CPU index.

## What needs to change
- Add `[dependency-groups] dev` (pytest, pytest-asyncio, pytest-alembic, pytest-bdd, pytest-cov, pytest-randomly, httpx, ruff, black, mypy) with pinned versions; set torch CPU index in `[tool.uv]`.
- Move pytest config into `core_backend/pyproject.toml`; switch Makefiles to `uv run`; remove/deprecate conda `fresh-env`.
- Dockerfile installs via `uv sync --frozen` (or a hash-pinned `uv export`), and either delete `requirements.txt` or generate it with `uv export --frozen` plus a CI drift check. Remove unused `slowapi`.

## Done when
- From `core_backend/`: `uv run pytest`, `uv run ruff check .`, `uv run mypy app` work after `uv sync`.
- Image builds from the lock; no workflow uses an unchecked `requirements.txt`.
