**Target:** dsem Level 3 · **Skill:** dsem-security

## What's wrong now
- `auth/routers.py:117-132` never checks `idinfo["email_verified"]`.
- `auth/routers.py:209-229` logs in any existing user whose username equals the Google email — no password, no link record (account-takeover path for password users with email usernames).
- Any Google account self-registers as ADMIN of a new workspace (`auth/routers.py:231-266`).

## What needs to change
- Reject tokens unless `email_verified` is true.
- Store Google `sub` / auth-provider on `UserDB` (Alembic migration); only log in Google-linked accounts this way; require explicit linking otherwise.
- Optional: `GOOGLE_ALLOWED_DOMAINS` allowlist for self-registration during internal testing.

## Done when
- With `verify_oauth2_token` mocked: `email_verified=False` → 401; a Google token matching an unlinked password user → 401/409.
- Migration applies on the test DB.
