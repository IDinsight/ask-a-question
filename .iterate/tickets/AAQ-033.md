## What's wrong now
- `get_similar_content_async` / `get_search_results` order by `cosine_distance` then filter `workspace_id` (`contents/models.py:~546-557`). HNSW returns ~40 global candidates (default `ef_search`) before filtering, so smaller tenants can get fewer than `n_similar` results.

## What needs to change
- Confirm pgvector version in `pgvector/pgvector:pg16`.
- Set `hnsw.iterative_scan = relaxed_order` per session (pgvector ≥ 0.8) or raise `hnsw.ef_search`; document the choice.

## Done when
- Test seeds 2 workspaces where A's content isn't in the global top 40 and still returns `n_similar` results for A.
