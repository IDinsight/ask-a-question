**Target:** dsem Level 3 · **Skill:** dsem-ci-cd (deploy-gcp.md, Level 3 staging deploy)

## What's wrong now
- Deploy workflows trigger independently on push (`deploy_gcp_core_backend.yaml:3-11`, admin:3-11) and never wait for tests/lint.
- Containers run `:latest` (core:122,150; admin:105,115) though `TAG` is computed (core:57).
- Staging/production logic mixed via `set-env` (core:25-41), duplicated across five files; skill wants workflows split by purpose at L3+.
- Caddy path filter `deployment/docker-compose/caddy/**` (`deploy_gcp_caddy.yaml:10`) matches nothing — Caddyfile is at `deployment/docker-compose/Caddyfile`.

## What needs to change
- `deploy-staging.yml` triggered by `workflow_run` on successful backend-ci and admin-app-ci on main (or reusable workflows with `needs:`); build/push and run `:${{ github.sha }}`.
- Keep release/dispatch production in a separate `deploy-production.yml`.
- Document `gcp-testing` as the staging environment; fix the Caddy path filter.

## Done when
- A merge with a failing test does not deploy; the image on the testing VM matches the merged SHA.
