**Target:** dsem Level 3 · **Skill:** dsem-security (references/nextjs.md), dsem-nextjs

## What's wrong now
- Token read/written in `localStorage` (`src/utils/auth.tsx:56,82-85,163`, `src/utils/api.ts:45`, `src/app/content/components/ContentModal.tsx:125`); any XSS (see S7) = account takeover. The Next.js security reference forbids browser token storage even at L1.
- No `server-only` module.

## What needs to change
- Set the session cookie from trusted server code: Next route handlers `src/app/api/auth/{login,logout,login-google}/route.ts` proxying to FastAPI, or backend `Set-Cookie` on `/login`.
- Flags: `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age` = JWT expiry. Backend admin routes accept the cookie; keep Bearer for API-key clients.
- Add `src/lib/api/server.ts` with `import "server-only"` reading `cookies()`.
- CSRF protection for cookie-authenticated mutations (strict Origin check or double-submit token).
- Remove every localStorage token read/write; serve username/role from a session endpoint.

## Done when
- Playwright: no token in localStorage/sessionStorage/JS-readable cookies after login; logout clears the cookie.
- Cross-origin POST without CSRF token / valid Origin → 403.
- `grep -rn 'localStorage.*token' src` returns nothing; importing `lib/api/server.ts` from a client component fails the build.
