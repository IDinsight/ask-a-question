## What's wrong now
- No `service.py` anywhere. `tags/routers.py` (344 lines) and `urgency_rules/routers.py` (348) call `models.py` functions that commit (3 commits each) and call the embedding API (`urgency_rules/models.py:92,140`).
- `models.py` mixes ORM classes and query functions; Alembic relies on `app/__init__` import side effects to see models.

## What needs to change
- `<feature>/service.py`: no FastAPI imports, `asession` first param, raises S1 domain errors, owns the single commit.
- `<feature>/persistence.py`: query functions moved from `models.py`, flush only, no external calls.
- `models.py` keeps ORM classes only; `app/models.py` imports all feature ORM modules.
- Document the convention (short `app/README.md` section) for the follow-up feature tickets.

## Done when
- Routers contain no queries, commits or business rules.
- Service unit tests (success, not-found, conflict, edge cases) run with `asession` and no TestClient.
- Existing API tests pass.
