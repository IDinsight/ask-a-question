**Target:** dsem Level 3 · **Skill:** dsem-security, dsem-api-setup

## What's wrong now
- `app/__init__.py:199` hard-codes `FastAPI(debug=True)`; unhandled exceptions return tracebacks to callers.
- No exception handlers registered anywhere (no `exception_handler` in `app/`). Domain errors (`UserNotFoundError`, `UserAlreadyExistsError`, `WorkspaceNotFoundError`, `EmbeddingCallException`, `LLMCallException`) are caught ad hoc or not at all (e.g. `UserAlreadyExistsError` from `users/models.py:1010`).
- Raw error strings leak to clients: `question_answer/routers.py:545,737` (upstream bodies via `speech_components/utils.py:223-225,239`), `question_answer/routers.py:1088` (`str(IntegrityError)`), `admin/routers.py:39-42` (unauthenticated healthcheck returns the DB exception), `docmuncher/dependencies.py:132,199,247,351`.

## What needs to change
- Read `debug` from settings (`ENVIRONMENT`), default `False`.
- Add `app/core/errors.py` with `NotFoundError`, `ConflictError`, `PermissionDeniedError`, `QuotaExceededError`, `ExternalServiceError`; make existing domain errors subclass them.
- Add `register_exception_handlers(app)` in `create_app`: 404 / 409 / 403 / 429 / 502 mappings plus a catch-all 500 `{"detail": "Internal server error"}` that logs the stack trace server-side.
- Replace `str(e)` / upstream bodies in client responses with generic messages; healthcheck returns `{"status": "error"}` only.

## Done when
- With default env, a test route raising `RuntimeError` returns 500 JSON with no traceback.
- Tests show each domain error maps to its status code.
- Healthcheck failure body contains no exception text.
- `grep` finds no `str(e)` / `{e}` inside `detail=` or `content=` in `app/`.
