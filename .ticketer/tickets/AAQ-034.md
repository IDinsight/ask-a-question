**Target:** dsem Level 3 · **Skill:** dsem-api-setup (database/variants/redis.md)

## What's wrong now
- `app.state.redis` used raw in 7 modules, no socket timeouts (`app/__init__.py:140`), no `RedisError` handling anywhere.
- Redis is cache (dashboard), state (quota counters `auth/dependencies.py:387-400`, docmuncher job state/locks) and chat history; healthcheck ignores it.

## What needs to change
- `app/core/redis.py`: pool, connect/socket timeouts, `get_redis` dependency, `get_cached`/`invalidate` helpers with DB fallback.
- Explicit, logged fail-open vs fail-closed decision for the quota limiter when Redis is down.
- Healthcheck reports `redis: ok|unreachable` (degraded = 200, DB down = 503).

## Done when
- Tests patching `get_redis` to raise show dashboard and content routes still work.
- Healthcheck test covers degraded state.
