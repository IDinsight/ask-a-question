**Target:** dsem Level 3 · **Skill:** dsem-security, dsem-api-setup (stacks/fastapi.md)

## What's wrong now
- No security headers in FastAPI, `deployment/docker-compose/Caddyfile` or `admin_app/next.config.js`.
- CORS (`app/__init__.py:218-229`) hard-codes `http://` and `:3000` origins in every environment, `allow_methods=["*"]`, `allow_headers=["*"]`, `allow_credentials=True` (not needed for bearer auth).
- `/metrics` mounted unauthenticated (`app/__init__.py:231-233`) and reachable at `${BACKEND_ROOT_PATH}/metrics` via Caddy.

## What needs to change
- FastAPI middleware (for non-Caddy GCP deploys) and Caddy `header` block: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, remove `Server`. Relax for `/docs` as needed.
- Read `CORS_ORIGINS` as a list from settings; HTTPS-only outside dev; explicit methods (GET/POST/PUT/PATCH/DELETE) and headers (Authorization, Content-Type); keep `allow_credentials` only if the cookie session (F2) is adopted.
- Block `/metrics` at Caddy or bind it to an internal port.

## Done when
- API test asserts the headers; `curl -I` on app and API shows them.
- Preflight from a disallowed origin gets no `Access-Control-Allow-Origin`.
- `/api/metrics` returns 404/403 externally.
