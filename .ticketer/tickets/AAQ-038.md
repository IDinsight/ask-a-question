**Target:** dsem Level 3 · **Skill:** dsem-api-setup (database/database.md)

## What's wrong now
- `core_backend/startup.sh:2` runs `alembic upgrade head` on every start; repo contains destructive revisions (e.g. `2025_02_23_79c762e9b073_dropping_old_attributes_for_workspaces.py`, `2024_07_17_30549f0b428a_drop_whatsapp_tables.py`). database.md L3 forbids running these automatically.

## What needs to change
- Guard script refusing auto-upgrade when a pending revision contains `drop_table`/`drop_column`/`drop_index` without an approval marker, plus a documented manual step (backup → upgrade); or move migrations to an explicit deploy step.

## Done when
- Test or CI check shows a pending drop migration blocks the automatic start path.
