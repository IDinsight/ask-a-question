**Target:** dsem Level 3 · **Skill:** dsem-api-setup (stacks/fastapi.md), dsem-security

## What's wrong now
- ~63 scattered `os.environ.get` calls across `core/config.py`, `auth/config.py`, `dashboard/config.py`, `question_answer/config.py`, `urgency_detection/config.py`.
- Unsafe defaults that never fail: `JWT_SECRET` placeholder default (`auth/config.py:7`, same value as `template.core_backend.env`), `POSTGRES_PASSWORD` default (`core/config.py:14`), `LITELLM_API_KEY` dummy default (`core/config.py:30`). Terraform generates a 16-char JWT secret (`deployment/gcp/.../credentials.tf`).
- Type bugs: `CHECK_API_LIMIT is False` can never be true from env (`auth/dependencies.py:382`, `core/config.py:87`); `CHECK_CONTENT_LIMIT="False"` is truthy (`core/config.py:84`); `DB_POOL_SIZE` arrives as a string (`core/database.py:105`); `DATABASE_URL` read but unused (`core/database.py:23`).
- `load_dotenv` side effect at import (`app/__init__.py:13-15`). `core_backend/.env.example` is ignored by `.*env*` in `core_backend/.gitignore:2`.

## What needs to change
- Single `Settings(BaseSettings)` in `app/core/config.py` with typed bool/int fields; feature configs read from it.
- `jwt_secret` has no default; refuse to start if it equals a known placeholder or is < 32 bytes. Outside `ENVIRONMENT=development` also refuse default `POSTGRES_PASSWORD` / `LITELLM_API_KEY`.
- Remove or wire `DATABASE_URL`. Raise terraform `random_password` length to ≥ 48.
- Update `tests/api/test.env` and CI env; un-ignore and commit `core_backend/.env.example` with placeholder values.

## Done when
- Importing/starting the app with `JWT_SECRET` unset or set to the placeholder raises a validation error (unit test).
- `CHECK_API_LIMIT=false` and `CHECK_CONTENT_LIMIT=false` actually disable the checks (unit test); `DB_POOL_SIZE` is an int.
- `.env.example` is tracked; CI still green.
