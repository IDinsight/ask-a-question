**Target:** dsem Level 3 · **Skill:** dsem-security

## What's wrong now
- `deployment/docker-compose/docker-compose.yml` publishes litellm_proxy on `4001:4000` with no `master_key` (anyone reaching the host can spend provider keys).
- Redis 6.0 (EOL) published on `6380` with no auth.
- core_backend loads `.litellm_proxy.env` (provider keys) though `core/config.py:28-29` says it only needs the proxy key.

## What needs to change
- Remove host `ports` for litellm and redis from the prod compose (keep them in `docker-compose-dev.yml`).
- Set `general_settings.master_key` from env and use it as the backend's `LITELLM_API_KEY`.
- Drop `.litellm_proxy.env` from core_backend's `env_file`.
- Redis: `requirepass` or internal-only; upgrade the image.

## Done when
- Prod compose publishes only 80/443.
- Unauthenticated litellm call from the backend network is rejected.
- Backend container env has no provider keys.
